A tese em uma frase

Transformar ferramentas isoladas numa plataforma em 3 camadas — Fundação (interna, compartilhada) · Transversais (consumidas, não recodificadas) · Domínios (features finas) — com engine de storage único e contratos de dados versionados.

As três camadas consomem para baixo e nunca para os lados — é o que mantém o acoplamento sob controle. O diagrama abaixo mostra essa direção.

Antes × depois

❌ Hoje (monolito de cópias)

  • 4 motores de storage paralelos
  • autenticação copiada em 3 lugares
  • contrato de dados implícito, sem versão
  • cada ferramenta re-implementa busca/export

Mudar uma regra exige tocar em N lugares → divergência silenciosa.

✔ Alvo (em camadas)

  • storage único na fundação
  • auth como serviço consumido
  • contratos versionados (schema validado)
  • busca/export viram transversais reaproveitadas

Uma regra muda num lugar só; as camadas acima herdam.
